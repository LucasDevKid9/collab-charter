# 知识库与潜空间语义场

> 宪章第十一章（11.1–11.4）的深度说明。回答四个问题：知识放在哪、
> 怎么被检索、权重从哪来、为什么可以信。

## 1. 这个子系统为什么存在

《模块化特征簇标记语法》把图像提示词拆成六大功能簇，靠一份**封闭集词库**
做归类。这份词库有三个先天局限：

1. **覆盖面有限**：只有约 150 条视觉词条，遇到新词只能报 `FCS001` 待人工判定；
2. **没有纵深**：知道"赛璐璐"属于哪个簇，不知道它与"平涂""Anime  cel"在语义上
   是什么关系、与"厚涂"为什么互斥；
3. **没有语料维度**：用户的真实需求越来越多地长在**互联网亚文化**里——
   "谷圈""痛包""晒谷""开盒"这类词不在任何美术词典里，却实实在在决定
   一次生成任务的语境。

第十一章把词库升级为**可扩容的知识库**（`knowledge/*.yaml`，当前 330 条，
覆盖字典 / 风格 / 亚文化三类），并给它配了三件分析工具：

| 工具 | 回答的问题 | 条款 |
|---|---|---|
| 向量征量空间 | 需求与哪条知识相近？相近多少？ | 11.2 |
| 潜空间语义场 | 这些知识之间谁是中枢、谁和谁同圈、哪些需求还没人接？ | 11.3 |
| 深挖引擎 | 给定需求 + 目标 + 语义状态，该带哪些词条、各占多大权重？ | 11.4 |

四件套的代码在 `src/collab_charter/lexicon/`（kb / vectors / field / mine），
MCP 侧对应 `lexicon_search` / `lexicon_mine` / `semantic_field` 三个工具。

## 2. 知识库存什么（11.1）

三个文件，一个约定：**词条数据只活在 YAML 里**，代码、测试、技能正文不得内联
（11.1-K1）。新增一类知识 = 新增一个 `knowledge/*.yaml` 文件，**零代码改动**
（`KnowledgeBase.load()` 扫目录全部文件，测试 `test_零代码扩容` 机械验证这条）。

```
knowledge/
├── lexicon.yaml       136 条  视觉词条本体（六大簇 / 类型 / 映射 / 权重梯度）
├── styles.yaml         46 条  风格域（艺术史 / 家族 / 时尚穿搭，权重上限 0.8）
└── subcultures.yaml   148 条  互联网亚文化（meme / slang / register / community / practice）
```

每条知识的字段设计遵循两个原则：

- **可溯源**（11.1-K2）：`source` + `confidence` 必填，两者都缺的条目进入
  `unverified` 名单，深挖引擎会在结果里点名警告——引用前先补来源；
- **可裁决**（11.4-M1）：`sensitivity` / `permission` 走第十章 3×3 闸门。
  "开盒""人肉搜索"这类词**收录的目的正是为了识别**：深挖遇到它们时输出
  `gate=block` 结论（clause 10-R3），而不是简单地不给搜。

**断链即错**：`related` / `conflicts` 指向不存在的条目 id，加载时直接抛
`KnowledgeBaseError`。语义场的边一半来自显式关联，断链等于边丢了，
不能静默。

## 3. 向量征量空间（11.2）

### 3.1 特征体系：四层权重

把每条知识表示成一个**精确的稀疏特征向量**（特征 → 权重字典，L2 归一化）：

| 层 | 特征形如 | 权重 | 例 |
|---|---|---|---|
| 词元 | `t:整词` | 1.0 | `t:赛璐璐` |
| 单字 | `t:单字` | 0.35 | `t:璐` |
| 元特征 | `c:/k:/d:/e:/g:` | 0.6 | `c:light`（簇）/ `k:style`（类型）/ `d:复古`（域）/ `e:2000s`（年代）/ `g:标签` |
| 释义 | `s:词元` | 0.35 | `s:平涂` |

再乘 **IDF**（稀有特征更 discriminative），上下文里出现的特征额外乘
**CONTEXT_BOOST = 1.6**——这是"语义状态影响分布权重"（11.4-M3）在空间侧的
实现机制：同一个"晒谷"，在上下文提到"谷圈"时权重上升。

**为什么不用 embedding**：330 条规模下，一个确定性、可复现、可逐特征解释的
稀疏向量比任何神经嵌入都更有用——它满足 11.2-V1（同输入同输出）、
11.2-V2（得分可分解到特征），而且**不引入随机性和外部在线状态**。

### 3.2 两个方向的诚实设计

- **条目侧保召回**：全量 n-gram（单字 + 相邻二元组）。"朋克"要同时命中
  "赛博朋克"和"蒸汽朋克"。
- **查询侧保精准**：拿知识库词表做**前向最大匹配**分词——"谷圈社群"切出整词
  `谷圈`，未命中段只取单字，**不产跨词边界二元组**。

这个不对称是实测逼出来的：早期两侧都产二元组时，缺口报告被"的人/感的/古质"
这类边界噪声占满；而哈希版本（hashing trick）在 330 条规模下竟能观测到
碰撞噪声——"赛璐璐"曾混进"谷圈"社群。**结论：这个规模不需要也不应该用
hashing trick**，精确稀疏向量既无碰撞，也让 `feature_weights` 可以直接
当归因输出。

### 3.3 空间指纹与"用后即弃"

`space_digest = sha256(空间版本 | 知识库 digest | 上下文 digest)`（11.1-K3
的延伸）：同一知识 + 同一上下文 → 同一指纹，挖掘过程可复现、可审计。

空间**按任务临时建构、用后即弃**（11.2-V3）：每次 `mine()` 调用都现场
`MeasureSpace.build()`，不缓存、不跨会话沉淀。测试
`test_空间任务期临时建构用后即弃` 验证两次构建不是同一个实例、而指纹相同。

## 4. 分布权重（11.2-V2）

深挖引擎给每个入选词条算一个分：

```
score = 相似度 × 先验权重 × 域增益(1.25) × 类型增益 [+ 探索期覆盖加分]
```

但**总分本身不是结论**。11.2-V2 要求"得分必须可分解到需求特征维度"，
所以每个词条输出：

- **分布权重**：`score / Σscore`，全体候选归一（和为 1）。它回答的是
  "这次任务的特征预算该怎么分"，而不是"这个词有多好"；
- **特征级归因**：词条的每个特征各贡献了相似度的多少份额——
  `t:晒谷` 占 61%、`t:晒` 占 18%……复盘时能精确看到"这条为什么入选"。

分布权重同时喂给下游：MCP 的 `lexicon_mine` 结果里 `weight` 字段就是它，
调用方（如技能层）据此决定提示词里各词条的括号权重。

## 5. 潜空间语义场（11.3）

对一次挖掘的候选集（通常 10–30 条）建构关联网络：

### 5.1 边怎么来

| 来源 | 权重 | 说明 |
|---|---|---|
| 显式 `related` | 0.5 | 知识库作者声明的关联 |
| 相似度 ≥ 0.10 | 实测 cosine | 空间侧自动涌现的关联 |
| 显式 `conflicts` | **断边** | 互斥词条之间不连边——语义场不连互斥的词 |

### 5.2 三个确定性算法

- **中心性**：幂迭代特征向量中心性，60 轮、均匀初始化、固定更新顺序。
  确定性是 11.3-F1 的硬要求（"社群划分不得使用随机初始化"）——
  同一个候选集，无论传入顺序如何，中心性数值一致（浮点求和次序除外，
  测试用 approx 比对）；
- **社群**：标签传播，按中心性降序 → id 升序的固定顺序更新。
  谷圈案例实测模块度 0.52，三个社群分明（[谷圈-痛包-吃谷-吧唧-晒谷] 等）；
- **覆盖缺口**：需求侧特征里，**没有被任何候选词条接住**的那些。
  输出形如 `t:千禧年`——可操作的缺口，而不是"覆盖率 73%"这种数字。

缺口分析过滤单字与停用字（"的/感/古"之类），否则报出来的全是边界噪声。

### 5.3 语义场结论的定位

11.3-F3 是一条容易被忽略的条款：**语义场结论是知识流的组织方式，不是事实流**。
"晒谷是谷圈社群的中枢"是对语料组织的描述，不等于"晒谷在事实上是中枢"；
条目的定义性内容仍以条目来源为准。MCP 输出里 `field` 与 `entries`
分开返回，就是让调用方不要把两者混为同一个置信等级。

## 6. 深挖引擎（11.4）

### 6.1 语义状态是显式输入

策略表（11.4-M3：状态必须显式传入，引擎不暗自假设）：

| 状态 | 类型增益 | 覆盖加分 | min_score | 意图 |
|---|---|---|---|---|
| 探索期 / 发散期 | 抽象 ×1.15、风格 ×1.15 | 0.35 | 0.02 | 多找、广覆盖 |
| 收敛期 / 聚焦期 | 实体 ×1.15、技术 ×1.15 | — | 0.06 | 收拢到可执行词条 |
| 创意期 | 风格 ×1.3、抽象 ×1.2 | 0.20 | 0.03 | 偏向风格域 |
| 校验期 | 实体 ×1.25、技术 ×1.25 | — | 0.08 | 只留高映射硬词 |
| （未识别） | 中性 | 0.10 | 0.03 | 告警后回落，不静默 |

同一个需求"谷圈 痛包 晒谷"，探索期会带回风格与抽象词，校验期只回
实体与技术词——**分布权重随语义状态重排**，这是 11.4-M3 的可观测效果。

### 6.2 选择与净化

- **MMR 去重选择**：相关性与多样性权衡（λ 随策略变化），避免选出的 12 条
  全是同一个词的不同写法；
- **跨文件同词去重**：lexicon 与 styles 各有一份"超现实主义"时，
  保留最高分者并在 warnings 里点名——同一结论出现两次会污染分布权重；
- **invalid 剔除**：规范显式禁止的词条（如"随机种子"）不进候选，
  并在 warnings 说明"如需求确实需要它，先改知识库再改需求"。

### 6.3 闸门与在线扩容

- 每个入选词条过第十章闸门；非「公开/可输出」的条目必须带裁决结论
  （11.4-M1）——"开盒"输出 `block`，clause 10-R3；
- `allow_online=True` 时引擎**只报闸门结论、不执行联网**（11.4-M2）：
  返回 `requires_user_confirmation=True` + `confirmation_clause=10-R4`，
  是否联网由用户决定，引擎不越权。

## 7. 诚实的边界

| 边界 | 说明 |
|---|---|
| **不是语义理解** | 全部基于词典子串 / n-gram / IDF，没有神经嵌入。同义改写（"徽章" vs "吧唧"）能靠 alias 接住，但接不住所有同义现象 |
| **规模上限** | 幂迭代 O(轮数×边数)、覆盖缺口 O(特征×候选)，330 条 / 30 候选内毫秒级；到万级条目需要近似最近邻，当前实现不假装支持 |
| **关联是概率性的** | 相似度 ≥0.10 建边是工程阈值，不是语义承诺；显式 related/conflicts 才是作者意图 |
| **社群无标准答案** | 标签传播的结果是"一种合理划分"，模块度只用于横向比较两次挖掘，不是绝对指标 |
| **缺口≠错误** | 缺口说"这个需求维度没有词条接住"，可能是知识库真缺，也可能是需求本身超出了知识库的领域 |
| **在线语料未接** | 11.4-M2 只定义了闸门口径，实时语料检索的实现留给后续版本；当前 allow_online 只产生报告 |

## 8. 三十秒上手

```python
from collab_charter.lexicon import KnowledgeBase, MiningRequest, mine

result = mine(MiningRequest(
    requirement="谷圈 痛包 晒谷",
    task_objectives=["整理徽章收藏圈的术语"],
    semantic_state="收敛期",
    limit=6,
))
for e in result.entries:
    print(e.term, e.weight, e.suggestion["example"])
print(result.field.metrics)          # 密度 / 模块度 / 社群数
print(result.field.gaps)             # 覆盖缺口
print(result.space_digest)           # 空间指纹（可复现锚点）
```

命令行等价物：

```bash
python3 -m collab_charter.cli kb                      # 知识库摘要
python3 -m collab_charter.cli mine "谷圈 痛包 晒谷" --state 收敛期
python3 -m collab_charter.cli field "谷圈 痛包 晒谷" --state 收敛期
```

MCP 工具：`lexicon_search` / `lexicon_mine` / `semantic_field`。
